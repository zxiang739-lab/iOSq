# VTFramePro 产品需求文档（PRD）

## 1. 项目信息

- **Language**: 简体中文
- **Programming Language**: Swift + SwiftUI（全部苹果原生 API：AVFoundation / VideoToolbox / CoreML / MPS；无第三方 UI 库、无 FFmpeg、无第三方推理运行时）
- **Project Name**: vt_frame_pro
- **原始需求复述**：开发一款纯 iOS App（VTFramePro），面向 Apple Silicon 神经引擎 iPhone，提供 AI 视频帧插值（补帧）与超分辨率处理能力。包含 3 种实时模式（摄像头实时流低延迟处理）与 2 种离线模式（本地视频文件高画质处理），内置自定义 AVPlayer 液态玻璃播放器，支持用户导入自定义 CoreML mlpackage 模型，UI 全部采用 SwiftUI 原生 Liquid Glass 效果。

## 2. 产品定义

### 2.1 产品目标

1. **实时处理体验**：基于摄像头实时流提供低延迟的 AI 补帧、超分及组合流水线处理能力，端到端延迟可控，实时性能状态可视化。
2. **高画质离线输出**：提供面向本地视频文件的异步离线补帧/超分处理任务队列，输出高质量结果视频并保存至照片库。
3. **模型可扩展**：内置默认模型 + 支持用户导入自定义 mlpackage，形成可管理的本地模型库，双链路（实时/离线）共用模型能力。

### 2.2 目标用户

- **视频创作者 / 短视频博主**：希望把手机拍摄的低帧率视频补成高帧率、把低清素材放大变清晰。
- **开发者 / AI 爱好者**：拥有自训练或下载的 CoreML mlpackage，希望在手机上本地推理验证效果。
- **影像玩家**：喜欢折腾实时预览效果的早期尝鲜用户，设备为 iPhone 15 Pro（A17 Pro）及以上。

### 2.3 用户故事

1. 作为视频创作者，我希望导入本地 30fps 视频并离线补帧到 60fps 输出，以便获得更流畅的成片。
2. 作为视频创作者，我希望把 720p 老素材离线超分到 4K 并保存到相册，以便二次剪辑。
3. 作为影像玩家，我希望打开摄像头实时预览补帧/超分效果，并看到 FPS、延迟和 GPU 占用，以便评估手机端实时能力。
4. 作为开发者，我希望导入自己的 mlpackage 模型并在实时/离线链路中切换使用，以便快速验证模型效果。
5. 作为普通用户，我希望离线处理任务可以后台排队、随时取消，并且处理完成后在系统相册里找到结果视频。

## 3. 技术规范

### 3.1 需求池（Requirements Pool）

| 编号 | 优先级 | 需求 | 说明 |
|---|---|---|---|
| R-01 | P0 | 实时补帧 | 摄像头输入，仅 AI 帧插值，不放大分辨率，CMSampleBuffer 实时流转预览 |
| R-02 | P0 | 实时超分 | 摄像头输入，仅 AI 超分，不做帧插值，实时预览 |
| R-03 | P0 | 实时补帧+超分 | 流水线串联补帧插值 + 超分放大，实时预览 |
| R-04 | P0 | 离线补帧 | 导入本地视频，AI 帧插值输出新视频，分辨率不变 |
| R-05 | P0 | 离线超分 | 导入本地视频，AI 超分放大输出新视频，不补帧 |
| R-06 | P0 | 播放器-进度条拖拽 | 拖动滑块跳转，拖动中实时预览目标时间点 |
| R-07 | P0 | 播放器-点击画面 | 显示/隐藏液态玻璃控制面板 |
| R-08 | P0 | 播放器-长按加速 | 长按画面临时高速倍速，松开恢复原速率 |
| R-09 | P0 | 播放器-档位倍速 | 0.5x / 1.0x / 1.5x / 2.0x，AVPlayer 原生 rate |
| R-10 | P0 | 状态面板 | 实时链路显示 FPS、端到端延迟、GPU 占用 |
| R-11 | P0 | 权限申请 | 摄像头、照片库读写权限，未授权时友好引导 |
| R-12 | P0 | 错误处理 | Cocoa Error（NSError 域）统一错误体系，界面友好错误提示 |
| R-13 | P0 | 模型导入 | 用户导入自定义 mlpackage，本地模型库列表管理 |
| R-14 | P0 | 离线任务队列 | 异步任务队列、任务可取消、进度可见 |
| R-15 | P0 | OOM 内存保护 | 分批分帧处理，内存压力降级/中止策略 |
| R-16 | P0 | 结果保存相册 | 离线完成后保存到照片库并提示 |
| R-17 | P0 | Liquid Glass UI | 全部 SwiftUI 原生玻璃材质（.glassBackgroundEffect() 等） |
| R-18 | P1 | 内存复用优化 | CMSampleBuffer / CVPixelBuffer 池化复用，降低实时链路分配开销 |
| R-19 | P1 | 模型校验与元信息 | 导入时校验 mlpackage 输入输出张量规格，显示模型名称/用途（补帧或超分） |
| R-20 | P1 | 模型切换 | 实时/离线处理前可选当前生效模型 |
| R-21 | P1 | 处理参数设置 | 超分倍数、补帧倍率（x2/x4）、实时链路分辨率/画质档位 |
| R-22 | P1 | 实时录制保存 | 实时预览结果可录制保存为视频（可选） |
| R-23 | P2 | 处理历史 | 离线任务历史记录与结果回放入口 |
| R-24 | P2 | 热管理提示 | 设备发热时提示降档建议 |
| R-25 | P2 | 深色/浅色适配、无障碍 | 系统外观自适应、VoiceOver 基础支持 |

**明确不做**：离线「补帧+超分」组合模式；macOS 版本；任何第三方推理运行时 / FFmpeg。

### 3.2 UI 页面清单与交互说明

| 页面 | 主要内容 | 关键交互 |
|---|---|---|
| 主界面（Home） | 模式入口：实时补帧 / 实时超分 / 实时补帧+超分 / 离线补帧 / 离线超分；模型管理入口；设置入口 | 玻璃材质大卡片网格；点击进入对应流程；页面顶部显示当前生效模型 |
| 实时预览页 | 摄像头实时预览画面 + 液态玻璃状态面板（FPS / 延迟 / GPU 占用）+ 控制条 | 启动/停止处理；切换模型与画质档位；点击状态面板展开详细指标；权限未授权时显示引导 |
| 离线任务页 | 视频导入入口、任务队列列表（进度、状态、取消按钮）、历史任务 | 选择视频 → 创建任务 → 排队执行；滑动/按钮取消任务；任务完成点击进入播放器预览并可保存相册 |
| 播放器页 | 自定义 AVPlayer 播放器 + 液态玻璃控制面板 | ①进度条拖拽并拖动中预览；②点击画面切换面板显隐；③长按画面高速倍速、松开恢复；④0.5x/1.0x/1.5x/2.0x 档位倍速 |
| 模型管理页 | 内置模型 + 用户导入模型列表；模型详情（名称、类型、规格） | 导入 mlpackage 文件（文件选择器）；删除自定义模型；设为当前模型；校验失败提示 |
| 设置页 | 处理参数默认值（补帧倍率、超分倍数、实时画质档位）、权限状态、存储占用、关于 | 修改默认参数；跳转系统设置开启权限；清理缓存/中间文件 |

### 3.3 待确认问题（Open Questions）

1. **部署版本**：iOS 18+ 还是 iOS 26+？（影响 Liquid Glass API 可用性，由架构师最终确认）
2. **内置模型来源**：内置默认补帧/超分模型是自研转换还是采购授权 mlpackage？模型体积预算？
3. **实时档位定义**：实时模式的输入分辨率上限（720p/1080p？）与目标端到端延迟指标（如 <100ms）需量化。
4. **离线输出规格**：超分倍数范围（x2/x4？）、输出编码格式（H.264/HEVC）、码率策略。
5. **自定义模型约束**：对导入 mlpackage 的输入输出张量形状/颜色空间约定（否则无法通用化推理）。
6. **实时录制保存**（R-22）是否进入首版本范围？
7. **任务并发**：离线任务队列是否允许并发执行，还是严格串行？
8. **免费/付费策略**：是否考虑功能限制（如导出时长、去水印）与内购？
