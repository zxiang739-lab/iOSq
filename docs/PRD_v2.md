# VTFramePro 产品需求文档（PRD）v2.0

> 本文档为 v1.0 的增量升级版，**以用户最新规格为权威基准**。v1.0 待确认问题已全部拍板（见 3.4 节）。v1.0 原文保留于 PRD.md，本文档独立生效。

## 1. 项目信息

- **Language**: 简体中文
- **Programming Language**: Swift + SwiftUI（iOS 26 Liquid Glass 原生 API；AVFoundation / VideoToolbox VTFrameProcessor / CoreML / MetalPerformanceShaders；**禁止**私有 API、FFmpeg 及任何第三方 SDK/依赖）
- **Project Name**: vt_frame_pro
- **平台范围**: 纯 iOS App（**不做 macOS**），部署目标 iOS 26，完整兼容 iOS 27，仅使用 WWDC25/26 官方公开 API
- **原始需求复述**：开发一款纯 iOS App（VTFramePro），采用「双 AI 引擎 + 统一抽象协议」架构：引擎① 系统 VTFrameProcessor（仅 iOS 26+，运行时能力检测）；引擎② 用户导入 CoreML mlpackage（CoreML + MPS，模型不内置）。提供 5 种业务模式——实时补帧 / 实时超分 / 实时补帧+超分串联（AVCaptureSession + CMSampleBuffer 流转），离线补帧、离线超分（AVAssetReader/AVAssetWriter，任务可取消、分批防 OOM、完成存照片库）。内置自定义 SwiftUI AVPlayer（Liquid Glass 控制面板），UI 全部 SwiftUI 原生 Liquid Glass 效果。交付完整可运行 Xcode 工程，可直接提交 GitHub。

## 2. 产品定义

### 2.1 产品目标

1. **双引擎可切换的实时体验**：系统 VTFrameProcessor 引擎与用户导入 CoreML 引擎经统一协议抽象，UI 不直接触碰推理；实时链路低延迟（端到端 <150ms）、低内存拷贝，性能状态（FPS/延迟/硬件占用）可视化。
2. **高画质离线输出**：离线补帧/超分任务严格串行队列执行，可取消、分批处理防 OOM，输出 HEVC 视频（超分 x2 VT 高质量档）保存至照片库。
3. **模型生态零内置、可扩展**：不内置任何 mlpackage；系统能力交给 VTFrameProcessor（含系统模型下载状态管理），自定义能力由用户导入并校验张量规格，形成可信本地模型库。

### 2.2 目标用户

- **视频创作者 / 短视频博主**：把低帧率/低清素材离线增强后用于成片。
- **开发者 / AI 爱好者**：在 iPhone 本地验证自训练 CoreML 补帧/超分模型。
- **影像玩家**：尝鲜 iOS 26 VTFrameProcessor 实时 AI 视频能力，设备需 iPhone 15 Pro（A17 Pro）及以上（以运行时 `.isSupported` 检测为准）。

### 2.3 用户故事

1. 作为视频创作者，我希望导入本地视频离线补帧/超分（x2、HEVC）并保存到相册，以便获得高质量成片。
2. 作为影像玩家，我希望打开摄像头实时预览补帧/超分/串联效果，并看到 FPS、端到端延迟和硬件占用，以便评估实时能力。
3. 作为开发者，我希望导入自己的 mlpackage（经张量校验通过后入库）并在实时/离线链路中与系统 VT 引擎自由切换，以便对比验证模型效果。
4. 作为 iPhone 15 Pro 用户，当设备不支持系统 VT 引擎时，我希望对应入口置灰并看到友好提示，而不是点击后报错。
5. 作为普通用户，当系统 VT 模型尚未下载完成时，我希望看到「下载中/失败/完成」的明确状态，并能重试；离线任务可排队、可取消，完成后在系统相册找到结果。

## 3. 技术规范

### 3.1 需求池（Requirements Pool）

> v2.0 新增/变更条目以 ★ 标注；R-22 实时录制**移出首版**。

| 编号 | 优先级 | 需求 | 说明 |
|---|---|---|---|
| R-01 | P0 | 实时补帧 | AVCaptureSession 摄像头输入（上限 720p），仅帧插值，CMSampleBuffer 实时流转预览，减少内存拷贝（CVPixelBuffer 直通/池化） |
| R-02 | P0 | 实时超分 | 摄像头输入，仅超分，实时预览，同上 |
| R-03 | P0 | 实时补帧+超分 | 流水线串联：插值 → 超分，实时预览，同上 |
| R-04 | P0 | 离线补帧 | AVAssetReader/AVAssetWriter 导入本地视频，帧插值输出新视频，分辨率不变，HEVC 编码 |
| R-05 | P0 | 离线超分 | 离线超分 x2（VT 高质量档配置），HEVC 编码输出 |
| R-06 | P0 | 播放器-进度条拖拽 | 拖动滑块跳转，拖动中实时预览目标时间点 |
| R-07 | P0 | 播放器-点击画面 | 显示/隐藏液态玻璃控制面板 |
| R-08 | P0 | 播放器-长按加速 | 长按临时高速倍速，松开恢复原速率 |
| R-09 | P0 | 播放器-档位倍速 | 0.5x / 1.0x / 1.5x / 2.0x，AVPlayer 原生 rate |
| R-10 | P0 | 状态面板 | 实时链路显示 FPS、端到端延迟（目标 <150ms）、硬件占用（ANE/GPU/CPU） |
| R-11 | P0 | 权限申请 | Info.plist 含摄像头、照片库、文件导入全部隐私键；未授权时友好引导 |
| R-12 | P0 | 错误处理 | 统一错误体系（引擎不可用/模型校验失败/下载失败/内存压力），界面友好提示 |
| R-13 | P0 | 模型导入 | 文件选择器导入补帧/超分 mlpackage，**存入 App 沙盒（不内置）**，本地模型库列表管理 |
| R-14 | P0 | 离线任务队列 | **严格串行**异步队列、任务可取消、进度可见 |
| R-15 | P0 | OOM 内存保护 | 分批分帧处理，内存压力下降级/中止策略 |
| R-16 | P0 | 结果保存相册 | 离线完成后保存到照片库并提示 |
| R-17 | P0 | Liquid Glass UI | 全部 SwiftUI 原生玻璃材质（`.glassBackgroundEffect()` 等 iOS 26 API） |
| ★R-26 | P0 | 引擎抽象协议 | 统一 AI 引擎协议（补帧/超分接口、能力查询、状态回调），UI → ViewModel → 媒体服务层 → AI 引擎协议层 → Model 五层架构，UI 不直接调用推理 |
| ★R-27 | P0 | 引擎实现拆分 | `VTFrameProcessorEngine`（系统 VT 引擎）与 `CoreMLImportEngine`（CoreML+MPS）双实现，可运行时切换 |
| ★R-28 | P0 | VT 能力检测与置灰 | 系统 VT 引擎启动时 `.isSupported` 运行时检测；不支持的设备相关入口置灰 + 友好提示文案 |
| ★R-29 | P0 | VT 实时/离线配置分档 | 实时链路用 VTLowLatency 配置；离线链路用 VT 高质量超分/帧率转换配置 |
| ★R-30 | P0 | 系统模型下载状态 UI | 处理系统 VT 模型「下载中 / 失败（可重试）/ 完成」三态，界面明确展示 |
| ★R-31 | P0 | 引擎不可用降级策略 | 系统 VT 不可用 → 自动引导切换已导入 CoreML 引擎；无可用引擎 → 禁用处理入口并说明原因 |
| ★R-32 | P0 | 张量规格校验 | 导入 mlpackage 时校验输入/输出张量：像素格式为 RGB interleaved 或 `kCVPixelFormatType_32BGRA`；输入/输出形状、批次、通道数须与声明用途（补帧/超分）匹配（详见 3.4 第 5 条）；校验失败拒绝入库并提示原因 |
| R-18 | P1 | 内存复用优化 | CMSampleBuffer / CVPixelBuffer 池化复用，降低实时链路分配与拷贝开销 |
| R-19 | P1 | 模型元信息 | 模型库显示名称/用途/张量规格摘要；删除自定义模型 |
| R-20 | P1 | 引擎与模型切换 | 处理前可选当前生效引擎（系统 VT / 某个已导入 CoreML 模型） |
| R-21 | P1 | 处理参数设置 | 补帧倍率（x2/x4）、实时链路画质档位（720p 上限内）等默认值设置 |
| R-23 | P2 | 处理历史 | 离线任务历史记录与结果回放入口 |
| R-24 | P2 | 热管理提示 | 设备发热时提示降档建议 |
| R-25 | P2 | 深色/浅色适配、无障碍 | 系统外观自适应、VoiceOver 基础支持 |

**明确不做**：macOS 版本；离线「补帧+超分」组合模式；任何第三方依赖/SDK/FFmpeg/私有 API；内置 mlpackage；R-22 实时录制保存（不进首版）；付费/内购（免费无内购）。

### 3.2 UI 页面清单与交互说明

| 页面 | 主要内容 | 关键交互 |
|---|---|---|
| 主界面（Home） | 5 种模式入口卡片：实时补帧 / 实时超分 / 实时补帧+超分 / 离线补帧 / 离线超分；模型管理与设置入口；顶部显示当前生效引擎/模型 | 玻璃材质大卡片网格；设备不支持系统 VT 时对应入口**置灰 + 原因提示**；点击进入对应流程 |
| 实时预览页 | 摄像头实时预览 + 液态玻璃状态面板（FPS / 端到端延迟 / 硬件占用）+ 控制条 | 启动/停止处理；切换引擎/模型与画质档位；**系统 VT 模型下载中/失败/完成状态提示与重试**；权限未授权引导 |
| 离线任务页 | 视频导入入口、严格串行任务队列（进度、状态、取消按钮）、历史任务 | 选视频 → 选引擎/模式 → 创建任务排队；取消任务；完成点击进入播放器预览并可保存相册 |
| 播放器页 | 自定义 SwiftUI AVPlayer + 液态玻璃控制面板 | ①进度条拖拽拖动中预览；②点击画面切换面板显隐；③长按高速倍速、松手恢复；④0.5x/1.0x/1.5x/2.0x 四档倍速 |
| 模型管理页 | 引擎分区列表：系统 VT 引擎（含能力检测与下载状态）+ 用户导入模型 | 文件选择器导入 mlpackage；**张量校验，失败给出具体原因**；删除自定义模型；设为当前引擎/模型 |
| 设置页 | 默认处理参数、权限状态、存储占用、关于 | 修改默认参数；跳转系统设置开权限；清理缓存/中间文件 |

### 3.4 v1.0 待确认问题 → v2.0 拍板结论

| # | v1.0 问题 | v2.0 结论 |
|---|---|---|
| 1 | 部署版本 | **iOS 26** 部署目标，完整兼容 iOS 27（仅用 WWDC25/26 公开 API） |
| 2 | 内置模型来源 | **不内置任何模型**：仅系统 VT 模型（由系统下载管理）+ 用户导入 mlpackage（存 App 沙盒） |
| 3 | 实时档位 | 输入分辨率上限 **720p**；端到端延迟目标 **<150ms** |
| 4 | 离线输出规格 | 超分 **x2**（VT 高质量档）；输出编码 **HEVC** |
| 5 | 自定义模型张量约定 | 像素格式：**RGB interleaved 或 kCVPixelFormatType_32BGRA**。校验规则：①输入/输出张量数与声明用途匹配（补帧：2 帧输入→1 帧输出；超分：1 帧输入→1 帧输出）；②通道数与像素格式一致（3 通道 RGB 或 4 通道 BGRA）；③超分模型输出 H/W 必须为输入的整数倍（首版约定 x2/x4）；④批次 = 1；⑤形状静态（不接受动态 shape）。任一不满足即拒绝导入并提示具体原因 |
| 6 | R-22 实时录制 | **不进首版**（移出范围） |
| 7 | 任务并发 | 离线任务**严格串行**队列 |
| 8 | 免费/付费 | **免费，无内购**，不做功能限制 |
